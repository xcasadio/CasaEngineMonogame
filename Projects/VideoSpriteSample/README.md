# VideoSpriteSample

A project with no gameplay DLL that plays a synthetic MDEC clip as a sprite of the world, with another sprite fading in over it, from data alone (ADR-0130). `VideoSpriteWorld.world` starts `Cutscenes/loop.cutscene` through its `startup_cutscene_asset_id` key. The project's `FirstScreenName` is empty: there is no screen.

## Objective

Show the world video component, the `PlayVideoSprite` action and the `AnyKey` input device with no code of the game:

1. `VideoSpriteWorld.world` holds a 2D camera (320x180 design resolution), a black clear colour, and two entities hidden at load: `clip`, whose root component is a `VideoSpriteComponent` (`video` names the catalogued clip, scale 1.5, Z 1), and `orb`, a `StaticSpriteComponent` at Z 0. The larger Z is drawn first, so the sprite is drawn after the video and blends over it. The video does not test or write depth, so the sprite is not rejected by it.
2. `Cutscenes/loop.cutscene` arms `ExitOnInput` (mapping `sample-input`, input `exit`, next cutscene `VideoSpriteExit`), then runs an endless `Repeat`. Each turn is a `Parallel` of two branches: `PlayVideoSprite` on `clip` (it shows the entity, plays the clip from its first picture, waits for its end, hides the entity), and a sequence that waits one second, shows `orb` in additive mode at black, tints it to a warm colour (it fades in over the video), then back to black. A `HideSprite` and a short `Wait` close the turn.
3. `Cutscenes/exit.cutscene` runs a `FadeScreen`, then a `ChangeWorld` to `EndWorld.world`.
4. `EndWorld.world` is a black world whose startup cutscene (`Cutscenes/end.cutscene`) waits 2 seconds, clears the exit overlay, then changes back to `VideoSpriteWorld.world`, so the sample runs for ever.
5. `Videos/clip.mdecvideo` is the clip: 160x112 pixels, 60 frames at 15 frames per second (4 seconds), no sound, generated by `CasaEngine.Tests/Video/VideoSampleClip.cs`. It is the same file as `Projects/VideoSample/Videos/clip.mdecvideo`. `Images/shapes.png` is generated by `CasaEngine.Tests/Cutscenes/SpriteCutsceneSampleImages.cs`, and is the same file as in `Projects/SpriteCutsceneSample`. `VideoSpriteSampleDataTests` checks that both equal their generators.

## Controls

The `sample-input` mapping holds one input, `exit`.

| Action | Keyboard | Game pad |
|---|---|---|
| Leave: fade, then the end world | any key | Start |

`AnyKey` reacts to each new key press, except Shift, Ctrl, Alt and Windows alone, and nothing happens while Alt or Windows is held: Alt+Tab, Alt+F4 or Windows+D do not leave. A key held while the cutscene starts does not trigger the exit: release it, then press a key again. The game pad is read even when the window has no focus. After the end world the sample starts again. Close the window to quit.

## Run

From the repository root:

```bash
dotnet run --project CasaEngine.Launcher -- Projects/VideoSpriteSample/VideoSpriteSample.json
```

## What to look at

- The clip plays centred, the orb fades in over it in the middle of the clip, then the clip ends and the turn starts again.
- `VideoSpriteWorld.world`: the `video` key of the `VideoSpriteComponent` and the Z of the two entities.
- `Cutscenes/loop.cutscene`: the `Parallel` of `PlayVideoSprite` and the sprite sequence.
- `sample-input.buttonsMapping`: the `exit` entry with `"input_device": "AnyKey"` (its `key`, `game_pad_button` and `mouse_button` are read and ignored) and the game pad Start as alternative.
- `AssetInfos.json`: the clip is catalogued as `mdecvideo`; `video` is its catalogue name.
