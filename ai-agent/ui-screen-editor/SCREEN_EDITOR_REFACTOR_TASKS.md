# UI Screen Editor — Post-V1 Refactor Backlog

This document lists improvements deferred from the v1 milestone, prioritised for
a future iteration. Each entry references the relevant code area and describes
the expected benefit.

---

## Priority 1 — High Impact, Manageable Scope

### R-01 Incremental preview update
- **Area:** `UIScreenPreviewBuilder`, `UIScreenPreviewPanel`
- **Problem:** Every property edit triggers a full XAML re-parse and element construction
- **Solution:** Detect the precise MGElement that maps to the changed node and mutate its properties in-place (e.g. `element.Text = newValue`), bypassing a full rebuild
- **Benefit:** Property-edit latency drops from ~50ms to < 1ms; eliminates selection flicker
- **Prerequisite:** Type-safe property reflection API or per-element typed setters

### R-02 Drag-to-move respects layout containers
- **Area:** `UIScreenPreviewPanel`, `OnScreenNodeMoveRequested` in Game1
- **Problem:** Applying Margin deltas to nodes inside `MGStackPanel` or `MGDockPanel` has no visual effect because parent layout overrides margin
- **Solution:** Detect the node's parent container type; for layout-driven parents, transform the move into a reorder (change child order) rather than a margin change
- **Benefit:** Visual move is predictable and correct for all container types

### R-03 Single-pass node map indexing
- **Area:** `UIScreenPreviewBuilder.BuildWithMapping`
- **Problem:** `window.TryGetElementByName` does a linear scan per node ID → O(N²) for large screens
- **Solution:** Expose a bulk `window.GetAllNamedElements()` dictionary from MGUI, or do a single DFS pass collecting all named elements before mapping
- **Benefit:** Preview mapping of 200-node screen drops from ~40ms to ~1ms

### R-04 Hierarchy panel diffing
- **Area:** `UIScreenHierarchyPanel.SetDocument`
- **Problem:** Full `TryRemoveAll` + rebuild on every document change discards scroll position and expanded state
- **Solution:** Diffuse the new tree against existing nodes; only add/remove/rename changed nodes
- **Benefit:** Hierarchy remains stable during live edits; no scroll jump

## Priority 2 — Medium Impact

### R-05 Inspector row caching
- **Area:** `UIScreenInspectorPanel.SetNode`
- **Problem:** All rows are destroyed and recreated when the same node type is re-selected
- **Solution:** Cache rows per control type; only update values when re-selecting the same type
- **Benefit:** Selection feedback is near-instant for repeated clicks on same-type nodes

### R-06 Undo grouping for drag operations
- **Area:** `UICommandStack`, `SetPropertyCommand`
- **Problem:** Drag-to-move may push two commands (Width + Height), and property edits during drag each push a command → clutters history
- **Solution:** Add `BeginGroup` / `EndGroup` to `UICommandStack`; group all commands generated by a single drag/edit as one undoable operation
- **Benefit:** Undo feels natural: one Ctrl+Z reverses the entire move/resize, not individual axis/property

### R-07 XAML per-element validation
- **Area:** `UIScreenXamlParser`, `UIControlRegistry`
- **Problem:** Invalid property values (e.g. a string where int is expected) are silently accepted and only fail at preview build time with a cryptic error
- **Solution:** Add a `UIScreenValidator` pass after parsing; report errors per node+property
- **Benefit:** Editor shows inline warnings on the offending property row in the inspector

### R-08 Multi-selection
- **Area:** `UIScreenSelectionService`, `UIScreenHierarchyPanel`, `UIScreenPreviewPanel`
- **Problem:** Only one node can be selected at a time; multi-select via Shift/Ctrl-click is not supported
- **Solution:** Change `SelectedNodeId` to a `HashSet<DocumentNodeId>`; extend overlay drawing to highlight all selected elements; extend commands to operate on a set
- **Benefit:** Enables bulk move, delete, group, and property-apply operations

## Priority 3 — Long Term / Complex

### R-09 Styles and resource dictionaries
- **Area:** `UIScreenDocument`, `UIScreenXamlSerializer/Parser`
- **Problem:** No support for reusable styles across controls in the document model
- **Solution:** Add `Resources` section to `UIScreenDocument`; serialise as `Window.Resources` in XAML
- **Benefit:** Theme-level styling, reduced duplication, consistent appearance

### R-10 Data binding model
- **Area:** `UIScreenNode`, `UIScreenXamlSerializer/Parser`
- **Problem:** Values are always literal strings; no notion of bound properties
- **Solution:** Introduce a `UIScreenBindingValue` (alongside `UIScreenPropertyValue`) that stores a binding path + fallback; render at design time using `UIScreenMockDataContext`
- **Benefit:** Designer can wire `{Binding Player.Score}` and see mock `"12,500"` in preview

### R-11 Component / template library
- **Area:** `UIControlRegistry`, `UIScreenNodeFactory`
- **Problem:** Re-creating common patterns (e.g. "button row", "header+content+footer") is manual
- **Solution:** Allow saving a node subtree as a reusable template; expose in toolbox under "Templates"
- **Benefit:** Dramatically speeds up screen authoring for complex layouts

### R-12 Responsive layout helpers
- **Area:** `UIScreenPreviewPanel`, preview builder
- **Problem:** The current model uses fixed pixel sizes; no mechanism to define adaptive rules
- **Solution:** Add a `DesignConstraint` concept (grid columns, percentage widths, anchor points) that maps to MGUI's `HorizontalAlignment.Stretch` + proportional containers
- **Benefit:** Screens automatically adapt to portrait/landscape or different resolutions

### R-13 XAML hot-reload without full rebuild
- **Area:** `UIScreenPreviewPanel`, file watchers
- **Problem:** Saving the XAML file triggers a full `LoadAsset` → `BuildWithMapping` chain
- **Solution:** Use the incremental update path (R-01) triggered by the file watcher; only re-parse and re-apply the diff
- **Benefit:** Save-and-preview cycle drops from ~200ms to < 10ms
