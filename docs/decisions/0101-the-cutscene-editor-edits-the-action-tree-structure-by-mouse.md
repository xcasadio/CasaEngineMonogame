# ADR-0101: The cutscene editor edits the structure of the action tree by mouse

- **Status**: Accepted
- **Date**: 2026-11-18
- **Source**: this chantier: `ai-agent/tasks/cutscene-editor-structure-tasks.md` (decisions D1 to D5 settled with the author, choices P1 to P16 taken by the agent, approved with the plan on 2026-11-18 and open to correction at its acceptance), branch `chantier/cutscene-property-editing`. Completes ADR-0096 and ADR-0097, which deferred the moving, wrapping, copy and paste of actions.

## Context

- ADR-0097 let the outliner add, remove and duplicate actions, and deferred moving actions, wrapping them, copy and paste, and multiple selection. ADR-0096 made the timeline a projection of the action tree.
- The three containers (`Sequence`, `Parallel`, `Repeat`) keep their children in a list named `Actions`; `CutsceneLoadFidelity.GetChildren` returns it for them and `null` for the other actions (`CasaEngine.EditorServices/Cutscenes/CutsceneLoadFidelity.cs`).
- The loading losses of an edit session are attached to the instance of an action, not to its path. Removing an action drops those of its subtree and the undo restores them. `CutsceneLoadLoss.Path` is a string recorded at load time, and is already out of date after an insertion or a removal.
- `CutsceneActionCatalog.Clone` copies neither format errors nor unknown types. `InsertCutsceneActionCommand.GetDuplicateRefusal` refuses a duplicate for a subtree that carries an unknown type, a format error or a loading loss.
- The context menu of the outliner has two entries, `Duplicate` and `Delete`, and is not shown for the root. The outliner handles no key. The timeline control takes its context menu from an internal `ITimelineContextMenuProvider`; without a provider the default menu offers nothing for the cutscene timeline.
- The tree view of MGUI has a single selection. A row is selected by a click, and a press followed by a drag selects nothing. The element that wants a drag must mark `DragStart` as handled, otherwise the window takes it. A root `MGContextMenu` closes when the mouse goes away from it; a sub-menu is created with `new MGContextMenu(parentMenu)`.
- The global shortcuts of the editor (undo, redo, duplicate, copy, cut, paste, save) read the raw keyboard state and are suspended only for a modal window, an open context menu or a focused text entry. Duplicate, copy, cut and paste act only on the interface screen document, without looking at the kind of the active document. Delete is not a global shortcut; the content browser handles it on the key event of its tree.

## Decision

- **Move (P1).** Moving is a command of its own: the instance of the action changes place, without a copy, so it keeps its selection, its expanded state, its loading losses and its measured durations. The destination is a container and an index among the children of that container before the move. Refused: the root, a container dropped into itself or into one of its descendants, a destination that is not a container or not in the tree, an index out of bounds, and a move that changes nothing. The document operation receives the action to move, does not depend on the selection, and selects the moved action afterwards.
- **Wrap and ungroup (P2).** Wrapping replaces an action by a new `Sequence`, `Parallel` or `Repeat` created by the catalogue, which contains it; the root can be wrapped and the container becomes the new root. Ungrouping replaces a non-root container by its children, in order, at its place; an empty container is simply removed. The repeat count of an ungrouped `Repeat` is lost and comes back on undo.
- **Clipboard (P3).** One clipboard object belongs to the editor and is shared by all the cutscene documents. It keeps a copy of the copied action, and every paste inserts a new copy at the place the existing insertion rule gives for the selection. Cut is copy then delete; the root can be copied but not cut. Copy and cut are refused for a subtree that carries an unknown type, a format error or a loading loss, by the same rule as the duplication. It is not the system clipboard.
- **One action at a time (P4).** There is no multiple selection. Several actions are grouped by wrapping one and dragging the others into the container.
- **Drag and drop in the outliner, without changing MGUI (P5, P6, P7).** The panel listens to the left-button drag, finds the row under the pointer from the bounds of the row headers, and draws the marker itself. The band of a row runs from its top to the top of the next visible row (to its bottom for the last row), so no position between two rows is unanswered. Zones of a band: upper quarter is before, lower quarter is after, the middle is inside (last child) for a container; for a leaf, the upper half is before and the lower half after. After a container that is expanded and has children means first child of that container. A destination exists only when the pointer is inside the visible area of the tree scroll, on both axes; below the last row in that area it is the end of the root; above the first row there is none. The root row accepts only inside; its upper and lower quarters give a refused destination without a marker. Starting a drag does not change the selection; after an accepted drop the moved action is selected. The marker is a horizontal line at the indentation of the destination for before and after, and a frame around the row for inside; nothing when the destination is refused. The move happens only on release over an accepted destination, where it is computed again from the current pointer position. Releasing elsewhere, pressing Escape, rebuilding the tree or changing the document cancels the drag. No automatic scrolling near the edges and no automatic expansion of a collapsed container happen during a drag: dropping inside a collapsed container appends to its end. The finding of the destination is a pure computation of the editing services, tested without interface.
- **One context menu for the tree and the timeline (P8, P9, P12).** A single class builds the menu and it is opened from the tree and from the timeline, for the selected action. Entries: `Add` (sub-menu by category, then by type), `Wrap in` (`Sequence`, `Parallel`, `Repeat`), `Ungroup`, `Move up`, `Move down`, `Cut`, `Copy`, `Paste`, `Duplicate`, `Delete`. An entry whose operation would be refused is not shown. With no selection (right click in the empty area of the tree) only `Add` and `Paste` are offered, at the end of the root. `Move up` and `Move down` swap the action with its neighbour in the same container and never leave it. In the timeline, a right click on an item selects it and opens the common menu; no item moves by mouse there, which belongs to the free placement of a later slice.
- **Keyboard (P10, P11).** Ctrl+C, Ctrl+X, Ctrl+V and Ctrl+D go through the existing global shortcuts: when the active document is a cutscene they act on that document and on nothing else, otherwise they keep their present behaviour. Delete removes the selected action only when the action tree has the keyboard focus; it is not a global shortcut. There is no keyboard move: the arrows belong to the navigation of the tree.
- **Selection and expansion after an operation (P13).** The moved action stays selected; a wrap selects the container; an ungroup selects the first freed child, or nothing when the container was empty; a paste selects the copy. Every container that newly appears in the tree is shown expanded.
- **Automation and diagnostics (P14, P15).** The option `--cutscene-edit-ops "<op>;<op>;..."` applies one operation per frame after the existing selection and add options (`select`, `add`, `move`, `up`, `down`, `wrap`, `ungroup`, `copy`, `cut`, `paste`, `duplicate`, `delete`, `undo`, `redo`, `shortcut`, `menu`, `draghover`). A refused operation is written to the diagnostics and does not stop the following ones. The diagnostics write the tree plan, the result of each operation, the clipboard content and the state of the drag marker.
- **Unchanged (P16).** The `Add` button and the type list above the tree stay.
- The `.cutscene` format does not change, and neither do the runtime and MGUI.
- **Deferred:** multiple selection, dragging in the timeline and free placement on it, automatic scrolling and expansion during a drag, keyboard moves, dragging a type from a palette, dragging between documents, the system clipboard.

## Consequences

- A cutscene can be built and reorganised without editing text: by drag and drop in the tree, or by the context menu from the tree or the timeline, and every operation is undoable and replayed by the preview like any other edit.
- The editing services gain additive public types (move, wrap and ungroup commands, an action clipboard, a drop target resolver); the runtime and MGUI are untouched.
- Because the drag is built on the panel, the row geometry is read in place at each pointer event, and the visible-row structure is rebuilt only when the tree changes, so a drag allocates nothing.
- Pasting an action that names an entity absent from the preview world of another cutscene inserts it as is; the validator reports it.
- Known limit: the path stored in a loading loss is not updated when an action changes place, as after an insertion or a removal today.
- Known limits of the drag: no auto-scroll, no auto-expansion, one action at a time. The real mouse drag cannot be tried in the launched editor by automation; it is covered by tests with the mouse harness and by the `draghover` state, then by the author's acceptance.
