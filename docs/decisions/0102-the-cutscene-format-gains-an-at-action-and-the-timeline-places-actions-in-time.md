# ADR-0102: The cutscene format gains an At action, and the timeline places actions in time

- **Status**: Accepted
- **Date**: 2026-11-18
- **Source**: this chantier: `ai-agent/tasks/cutscene-editor-placement-tasks.md` (decisions D1 to D6, settled with the author, and choices P1 to P17, taken by the agent and to be confirmed by the author at the acceptance), branch `chantier/cutscene-property-editing`. Builds on ADR-0096 and ADR-0098, and amends the read-only rule of ADR-0098 without rewriting it.

## Context

- ADR-0096 decided that the action tree is the saved model of a cutscene and that the timeline is a projection of it. ADR-0098 made that projection read-only: dragging, resizing and free placement were deferred, and the `.cutscene` format was left unchanged.
- The tree has no way to say "this action starts at 1.5 s": time only comes from the order of a `Sequence` and from `Wait` actions. Inside a `Parallel`, every branch starts together. The pattern `Sequence[Wait, X]` already gives a delay, but as a shape of the tree, which a timeline would have to guess before changing it.
- The author was told before this slice that it adds one action to the format, and asked for it to be run in autonomous mode (decisions D2 and D4).
- Precedent for adding a container to the runtime: the `Repeat` action added its data class, its type constant, its validation, its serialization (writing, type table, reading), its coroutine factory case and its read-only document case, without changing the schema version. The serializer writes `schema_version = CutsceneAsset.CurrentVersion`. A type unknown to a loader is read as `UnknownCutsceneActionData`, which the validator refuses with an error.
- The generic timeline control lets an item be dragged when it is editable and movable; the drag is horizontal only and puts the start of the item on the cursor. On release it asks an edit policy and raises an event with the new time. The cutscene timeline creates all its items as read-only.

## Decision

- **The `At` action (P1).** The format gains one action type, `At`: `{"type": "At", "seconds": 1.5, "actions": [ ... ]}`. It waits `seconds`, counted from the instant it starts, then plays its children one after the other, like a `Sequence`. It is exactly equivalent to `Sequence[Wait(seconds), ...]`. Inside a `Parallel`, all the `At` actions start together, so `seconds` is the instant of the clip inside that block.
- **Why an action (P2).** The instant becomes explicit data that the timeline can read and change without guessing a tree shape, and the tree shows one node "At 1.5 s" instead of two. Rejected: a start time carried by every action, because it would change the meaning of `Sequence` and touch every type; a separate asset of tracks, because the action tree stays the saved model (D1).
- **Validation, default, schema (P3).** A missing `seconds` is 0; a negative value or a value that is not a number is a validation error (a format error reported on `seconds`, loading never throws); an empty list of children gives the existing warning of containers. The schema version does not change, as for `Repeat`: an older engine loads `At` as an unknown type and refuses the cutscene with an error, without playing it wrongly.
- **Projection (P4).** The children of an `At` are placed at the start of the `At` plus `seconds`, one after the other; the `At` holds the sequence for `seconds` plus the duration of its children. The `At` itself has no item on the timeline.
- **What can be dragged (P5).** One rule. Only the main item of an action can be dragged, not the "more" range of a `Repeat`. Starting from the action of the item and going up: (1) if the parent is an `At` and the node is its first child, the drag changes `seconds` of that `At`; if it is not the first child, nothing can be dragged; (2) if the parent is a `Parallel`, the drag wraps the node in an `At`, as one history entry; (3) if the parent is a `Sequence` or a `Repeat` and the node is its first child, the rule restarts with that parent as the node; otherwise nothing can be dragged; (4) at the root, nothing can be dragged. The cases apply in this order, at the first parent met.
- **Conversion (P6).** A drag converts by difference: new `seconds` = current `seconds` (0 for a wrap) + (drop time - current start of the item), aligned on 1/60 s and clamped to 0. It does not depend on an estimated start of the block. During the drag the item does not go below the instant where `seconds` would be 0. No snapping on other items in this slice. The control puts the start of the item on the cursor from the first move: that behaviour is kept.
- **Room after the end (P7).** The displayed duration is the real duration plus the larger of a quarter of the real duration and 2 s, so a clip can be dragged later than the current end. The playhead and the seeks stay clamped to the real duration. The zoom fit reads the duration of the projection, not that of the model.
- **Draggable look (P8).** A draggable item is recognized by a lighter left edge and by its tooltip; the others keep their current drawing.
- **Add at a time (P9).** A right click in the empty area of the tracks offers `Add here` (by category, then type). The action is created inside an `At` at the cursor time, appended to the target `Parallel`: the selected `Parallel`, otherwise the nearest `Parallel` ancestor of the selection. Without a target `Parallel`, the entry is not offered. The instant is counted from the start of that `Parallel` in the projection (the start of its first round when it is inside a `Repeat`), aligned on 1/60 s and clamped to 0. For this, the projection records the start of every container. The created action becomes the selection.
- **`At` in the editor (P10, P11).** `At` joins the containers of the editor: catalog (category Flow, created with 0 s), `Wrap in`, `Ungroup`, drag and drop "into", copy and paste. Its summary in the tree follows the one of `Wait`: type, two spaces, value ("At  1.5 s"). Ungrouping an `At` leaves its children in its place and drops its delay; undo gives it back. The field `Seconds` is edited in the Inspector like the one of `Wait`: it is the way to type an exact instant.
- **Keyboard and duplication (P12).** Ctrl + drag, which the generic control translates into a duplication, does nothing on the cutscene timeline: duplication goes through the menu and Ctrl+D. When the timeline has the focus and a draggable item is selected, the control marks Delete, Backspace, Ctrl+D and Ctrl+C as handled without doing anything (Ctrl+V is not, the tracks being not editable); the global shortcuts of the structure slice, which read the raw keyboard state, keep acting.
- **Measured durations (P13).** Measured durations stay attached to the actions. Moving a clip changes the document, so it clears the measures and replays the preview by the existing rules; until the preview has replayed, items whose duration is measured take their estimated duration and may move by as much.
- **Automation (P14).** The automation switch `--cutscene-edit-ops` gains two operations: `place:<seconds>` (places the selected action at that time of the timeline, as a drag released there; refused for an action with no main item, such as a container) and `addat:<Type>:<seconds>` (as `Add here` at that time). The diagnostics tell, for each item of the timeline, whether it can be dragged and by which rule.
- **Sample (P15).** `Projects/SpriteCutsceneSample/Cutscenes/stagger.cutscene`: a `Parallel` of four `At` that start four sprites in a cascade, declared in `AssetInfos.json` like the three others.
- **Not done (P16).** No resize of bars: a duration stays a property of the action, set in the Inspector. No move of a clip from one row to another: the row comes from the entity of the action.
- **Status (P17).** This record was written as `Proposed`, because the author had not yet seen the exact form of `At`. The author confirmed the form (the name `At`, the key `seconds` and the semantics) on 2026-11-18, after the implementation and its screenshots: the record is `Accepted`.

## Consequences

- An action can be placed at an exact instant, read and set in the tree and in the Inspector, and moved on the timeline by mouse with one undo step. The tree stays the saved model: no second source of truth.
- The format grows by one action type and nothing else. No existing key is renamed or removed, and no existing `.cutscene` file is rewritten. An engine without `At` refuses a cutscene that uses it instead of playing it wrongly.
- ADR-0098 stated that the timeline edits nothing. This record amends that rule for the items described by P5 only; ADR-0098 is not rewritten, and its other decisions (rows, durations, `Repeat`, measured durations, scrubbing) stand.
- Placement is by difference, so it stays correct whatever the estimated start of the block; but the displayed start of an item with an estimated duration may shift once the preview has measured it (P13).
- The branches of a `Parallel` start one update after it, so a clip placed at 0.5 s starts one frame later in the preview than its bar says: this is the existing behaviour of `Parallel`, not changed here.
- Deferred: resizing bars, snapping on other items, moving a clip to another row, multiple selection (one action at a time, D6), automatic conversion of existing cutscenes into placed clips, curves and keyframes per property.
